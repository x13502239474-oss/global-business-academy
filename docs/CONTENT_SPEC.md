# 讲义写作规范（并行写作统一标准）

本项目是 **GLOBAL BUSINESS ACADEMY 2.0**：国际社交媒体运营与海外市场营销自学平台。
技术形态：原生 HTML/CSS/JS，无构建。讲义以 JS 数据文件形式存在，由已有渲染器统一渲染。

## 一、文件格式

每个数据文件是一个 IIFE，向 `G.data.lessons` 注册课时对象：

```js
/* 讲义：MODULE 0X ...（说明本文件覆盖哪些课时） */
(function (G) {
  const L = G.data.lessons = G.data.lessons || {};

  L['x-1'] = {
    objectives: [
      '能说出……',
      '能判断……',
      '能完成……',
      '能解释……'
    ],
    sections: [
      { h: '本节要解决的问题', html: `<p>……</p>` },
      { h: '核心概念', html: `<p>……</p><table>……</table>` },
      { h: '机制与原理', html: `……` },
      { h: '操作步骤', html: `<ol><li>……</li></ol>` },
      { h: '商业场景', html: `……` },
      { h: '案例', html: `……` },
      { h: '常见问题与风险', html: `<ul><li>……</li></ul>` }
    ],
    summary: ['……', '……', '……', '……', '……'],
    terms: { '术语': '一句话解释', '术语2': '……' },
    official: ['平台官方帮助中心条目名 —— 核对 2026-11'],
    practice: '一句话实操任务（学员当节就能动手做的事）'
  };

  // 其余课时同上……

})(window.GBA = window.GBA || {});
```

**硬性约束**

- 必须使用 `L['课时id'] = {...}` 赋值形式；课时 id 由任务指定，不得改动。
- 字符串内使用反引号模板字面量写 HTML；**模板字符串内部不得再出现反引号**，不得出现 `${`（除非确实要拼接变量，但建议完全避免）。
- 不要写 `export` / `import` / `require`；不要新增全局变量。
- 每个 `html` 内**不写行内 style**，不写 `<h1>/<h2>`（渲染器自动编号），不写 `<script>`、`<img>`、外链。
- 允许的标签：`<p> <ul> <ol> <li> <table> <tr> <th> <td> <strong> <em> <code> <br>`，以及提示框：
  `<div class="callout"><span class="ct">要点</span>正文</div>`（中性）、
  `<div class="callout ok"><span class="ct">结论</span>…</div>`（正面）、
  `<div class="callout warn"><span class="ct">风险</span>…</div>`（警示）。
- 表格第一行用 `<tr><th>…</th></tr>` 作表头。
- 中文标点；专有名词保留英文原名（如 Reels、Advantage+、Conversions API）。

## 二、每节课的内容结构（7 段，顺序固定）

| 段 | 标题（必须逐字一致） | 要写什么 | 最低要求 |
|---|---|---|---|
| 1 | `本节要解决的问题` | 用一个真实困惑开场（"很多人以为……其实……"），点明不解决会付出什么代价 | ≥180 字 |
| 2 | `核心概念` | 3–6 个概念的准确定义 + 一个对照表（概念 / 是什么 / 用在哪 / 常见误解） | 含 1 个表格，≥4 行 |
| 3 | `机制与原理` | 为什么会这样：平台机制、算法逻辑、商业逻辑或理论依据。要说清"因果链"，不是罗列结论 | ≥350 字 |
| 4 | `操作步骤` | 编号步骤 7–10 步，每步写"做什么 + 怎么做 + 判断标准/产出物" | ≥7 步 |
| 5 | `商业场景` | 一个具体业务（B2B 或 B2C，注明行业与国家/地区）怎么用本节方法，含推演 | ≥300 字 |
| 6 | `案例` | 真实公开案例（可溯源、定性描述）**或**明确标注"教学示例"的推演案例 | ≥250 字 |
| 7 | `常见问题与风险` | 5–8 条"问题 → 原因 → 应对"，含合规风险 | ≥5 条 |

另加字段：

- `objectives`：4–5 条，动词开头（能写出／能判断／能设计／能解释），可验收。
- `summary`：5 条，是结论不是目录。
- `terms`：5–8 个术语，一句话定义。
- `official`：2–4 条官方来源条目名（不编造 URL 路径，写条目名即可）。
- `practice`：1 句话实操任务，具体到"产出什么文件/什么清单"。

## 三、深度标准（验收线）

> 字数口径统一为 **纯文本中文字符数**：先去掉所有 HTML 标签，再去掉空白（换行与缩进）。这个口径比"含标签字符数"更严格，也更接近读者真实看到的篇幅。

- 单节课 7 段合计 **不少于 3600 字**（纯文本口径），**达标区间 4000–6000 字**。
- 全课至少 **2 个表格**（每个表格都要有信息增量，不做装饰性表格）。
- 至少 1 处 `callout`（结论或风险）。
- 术语必须在正文中被真正解释过，不能只在 `terms` 里出现。
- 禁止空话：删掉"非常重要""值得注意的是""随着……的发展"这类填充句；每句话都要有信息量。
- 禁止"目录式"写作：不能只列"要点一、要点二"而不解释。
- 验收命令：`node tools/validate.js`（会按上述口径逐节判定）。

## 四、事实纪律（最重要）

先读 `docs/SOURCES.md`，它是唯一事实基线。写作时：

1. **官方规则**：只写机制级表述，并指向官方条目（如"Meta 广告政策中的'误导性声明'条款"）。**不编造**具体按钮位置、页面路径、后台层级名称。
2. **数值**：只有 `SOURCES.md` 第二节核查表里出现过的数字才能直接使用（如 Instagram 标签 5 个、YouTube 双档门槛）。其他数字若为教学演算，必须写"教学示例：假设……"。
3. **不写**：粉丝数、增长率、营收、转化率倍数、算法权重系数、"最佳发布时间"，除非标注为经验/示例。
4. **区分三类陈述**：
   - 官方规则 → 可在 `official` 字段列出条目；
   - 行业经验 → 正文写"行业经验，非官方规则"；
   - 教学示例 → 正文写"教学示例"。
5. **过时内容不写**：IGTV、Twitter 时代操作、旧版广告后台路径、批量涨粉/互赞群、"搬运涨粉"。
6. **不确定就不写**，或写"需按官方帮助中心当期核对"。

## 五、写作风格

- 面向**零基础但想做生意**的成年人：讲人话，先给结论，再给原因，再给动作。
- 每节开头先接住一个真实痛点，结尾给可执行动作。
- 多用"因为……所以……""如果不……就会……"的因果句，少用形容词。
- 平台差异要写透：同一个动作在不同平台的效果为什么不同。
- 中文为主，关键术语首次出现给英文原词。

## 六、交付前自检

写完后运行（在 `gba/` 目录）：

```bash
node -e "new Function(require('fs').readFileSync('js/data/lessons_xxx.js','utf8'))" && echo OK
```

并自查：

- [ ] 语法通过，无 `${` 误用，无反引号嵌套
- [ ] 每节课 7 段齐全，标题逐字一致
- [ ] 每节 ≥3600 字（纯文本口径，`node tools/validate.js` 判定）
- [ ] 至少 2 个表格、1 个 callout
- [ ] 无编造数字、无过时功能、无界面路径
- [ ] 术语与 `terms` 一致
